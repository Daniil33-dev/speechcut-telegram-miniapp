# Секреты и приватность

Публикация кода не даёт доступа к установленным ботам. Каждый устанавливающий создаёт свои ключи и отдельный бот.

- `.env.local`, `.env`, SSH-ключи, базы, исходники, QA-отчёты с текстом и подписанные URL не публикуются.
- На VPS секреты хранятся в `/etc/speechcut.env` с правами root:root 0600. Не включайте `set -x`, не отправляйте env или журналы с токенами в чат.
- Локальная форма Telegram слушает только 127.0.0.1:3079. Для настройки на сервере используйте SSH tunnel, затем остановите форму.
- `DEV_AUTH_ENABLED=true` допустим только локально. Production отказывает при этом флаге. Для доступа нужен Telegram initData и allowlist.
- Хранение приватное; ссылки имеют срок и подпись. Не публикуйте их: до истечения они дают доступ к конкретному файлу.
- Аудио передаётся AssemblyAI, текст — OpenAI. Ознакомьтесь с условиями провайдеров и используйте записи, на обработку которых у вас есть право.
- Удаление job пытается удалить transcript у AssemblyAI; при неудаче API возвращает `providerDeleted=false`. Автоматический долговечный повтор внешнего удаления пока не реализован. Проверяйте это отдельно.
- Backup содержит тексты и метаданные. До 7 суток они могут сохраняться после ручного удаления. Шаблон backup не копирует видео и не настроен на внешний сервер.
- Публичный многопользовательский сервис потребует отдельной проверки изоляции, квот, политики удаления, нагрузки и пользовательского согласия. Не отключайте allowlist ради распространения кода.

Если ключ всё же попал в GitHub, сначала отзовите его у провайдера, затем очищайте историю. Удаление строки новым commit не удаляет её из старых commits.

Перед публикацией запускайте `pnpm run audit:public`. Проверка ищет типичные ключи, персональные пути, неположенные файлы и сломанные ссылки; она дополняет ручную проверку. О подозрении на утечку не пишите публичный issue с ключами или записью пользователя.
